# 本机数据模型

更新日期：2026-11-12。状态：第 1 阶段（聊天记录入库与全文搜索）已实现；页面、学习记录、任务和记忆为设计，尚未建表。长期的会话 / Run / 归档设计见 [Session 会话与文件管理](session-storage.md)，本文在其方向上定义分阶段落地的范围，以及 NekoPapa 作为“个人助手”要管理的数据。

## 定位与原则

NekoPapa 是本地优先的个人助手：聊天、Coding、学习、笔记和总结的数据都保存在用户电脑上，由 AI 在授权范围内读取、整理和写入，形式上接近 Notion 加一个常驻助手。

- **一个权威来源**：每类数据只有一处可写的权威记录（SQLite 表或其中的 JSON 列）。搜索索引、摘要和统计都是派生数据，可以删除重建，不能反向写回。
- **ID 不变**：迁移不改写已有的会话、消息、联系人和项目 ID。新对象使用随机 UUID。
- **本机优先**：数据库在本机数据文件夹，不经过中间服务器。云端（Java）只负责账号、计费，以后再做按记录的同步；云端不是本机数据的权威。
- **失败不覆盖**：读取或迁移失败时阻止写入并显示原因；迁移前的原始文件保留为备份。
- **前端不传路径**：前端只能按宿主提供的命令和名称读写；文件位置由宿主决定（`src-tauri/src/app_data.rs`）。

## 位置

```text
<appData>/                          # macOS：~/Library/Application Support/app.nekopapa.desktop/
├── data/
│   ├── workspace.sqlite            # 本机数据库（WAL 模式，-wal / -shm 为运行时文件）
│   └── chat-threads.json.migrated  # 第 1 阶段迁移前的聊天记录文件，保留为备份
├── files/                          # 附件与生成的文件（第 3 阶段）
├── cache/                          # 可清理
└── logs/                           # 日志（预留）
```

浏览器预览没有数据库，聊天记录仍在浏览器存储中；测试使用临时目录，不指向用户的应用数据目录。

## 分阶段的数据

| 阶段 | 数据 | 权威记录 | 派生数据 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 聊天会话与消息 | `chat_threads.data`（整段会话 JSON，与原存储格式一致） | `chat_messages` 文本行、`chat_search` 全文索引 | 已实现 |
| 2 | Agent Run、工具调用、审批 | `runs`、`run_events`、`approvals`（见 session-storage.md） | 活动摘要 | 设计 |
| 3 | 附件与生成文件 | `files/` 中按内容哈希存放的文件 + `attachments` 记录所有权 | 预览缩略图（放 `cache/`） | 设计 |
| 4 | 页面与块（Notion 式） | `pages`（标题、图标、父页面、排序）、`blocks`（类型、内容 JSON、排序、修订号） | 全文索引、反向链接 | 设计 |
| 5 | 学习记录 | `study_sources`（资料）、`study_items`（题目、答案、批改、错因）、`study_reviews`（复习时间表） | 掌握度统计、知识库向量（可重建） | 设计 |
| 6 | 任务与记忆 | `tasks`（标题、状态、截止、来源）、`memories`（内容、来源对象、置信度、过期） | 每日 / 每周总结页（写成第 4 阶段的页面） | 设计 |

每张表都带 `created_at`、`updated_at` 和 `revision`；需要同步的表另带 `deleted_at`（软删除），为以后的按记录同步留出余地。

## 第 1 阶段：聊天记录

- `schema_migrations(version, applied_at)`：迁移按版本在事务中逐步执行。
- `chat_meta(key, value)`：存原聊天存储外层的字段（如 `legacyMigrated`）。
- `chat_threads(id, position, title, updated_at, contact_id, project, data)`：`data` 是会话的完整 JSON，读取时原样拼回 `{ version: 1, legacyMigrated, threads }`，前端的读取门禁、合并与重试逻辑不变。
- `chat_messages(thread_id, message_id, seq, role, text)`：从 `data` 提取的纯文本，随会话在同一事务中重建。
- `chat_search`：FTS5 全文索引（trigram 分词，中文无需分词词典）；少于 3 个字的查询改用子串匹配。

保存时宿主在一个事务中逐会话比较：内容没变的会话不重写，变了的会话更新并重建它的消息行和索引，已不存在的会话删除。首次打开数据库时，如果 `data/chat-threads.json` 存在且数据库为空，就导入并把原文件改名为 `.migrated`；导入失败时事务回滚，原文件不动，并报告原因。

快速搜索（侧栏与 Dock）在桌面应用中同时查询全文索引：命中消息正文的会话会出现在结果里，副标题显示命中片段。内存搜索只覆盖每个会话最后 4000 字，全文索引覆盖全部消息。

## AI 能读写什么

Agent 工具按权限模式（每次询问 / 自动接受编辑 / 仅计划 / 完全访问）审批，以下是上限：

| 数据 | 读取 | 写入 |
| --- | --- | --- |
| 聊天记录 | 当前会话直接读；其他会话通过搜索工具读，结果标明来源会话 | 不改写已有消息；只追加自己的回复 |
| 页面与块 | 可读 | 新建页面、追加块直接进行；修改或删除用户写的块需要确认（“仅计划”下只给出草稿） |
| 学习记录 | 可读 | 记录作答、批改和复习结果；删除需要确认 |
| 任务 | 可读 | 新建、更新状态；删除需要确认 |
| 记忆 | 可读 | 写入时标明来源对象；用户可在设置中查看、修改和删除每一条 |
| 设置、密钥 | 不提供工具 | 不提供工具 |
| 项目文件 | 见 Coding 执行层的权限规则 | 同左 |

## 记忆放在哪里

记忆属于本机数据，存在 `memories` 表里，不依赖后端。常见的记忆 SDK（如 mem0、Zep、Letta）本质上是“抽取 → 向量化 → 检索”的流程，既能连云端也能本机运行；NekoPapa 采用同样的流程，抽取和检索在本机用用户配置的模型与向量扩展完成。云端只在用户开启同步后保存加密副本。

## 备份与恢复

- SQLite 使用 WAL 模式；备份通过 SQLite 的在线备份接口生成一致快照，不直接复制 `-wal` / `-shm` 文件。
- 迁移前的原始文件保留在 `data/` 中，带 `.migrated` 后缀。
- 数据库无法打开时，聊天历史显示错误且不可写，不会用空数据覆盖。
