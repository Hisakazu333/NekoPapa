# 开发任务清单

更新日期：2026-10-04。共 33 项，全部为待开始；没有预设负责人和完成日期。阶段目标以 [迭代计划](iteration-plan.md)为准，数据规则以 [会话文档](session-storage.md)为准。

## 领取与完成规则

状态流转：待开始 → 进行中 → 待验收 → 已完成；外部条件缺失时记阻塞原因和解除条件。任务领取时在本表或对应工作记录补负责人、代码位置和验证链接。

每项需提交可使用的动作、失败路径和证据；涉及数据的任务附迁移 / 恢复结果。新增入口必须指向真实模块。表中的“计划代码位置”尚未创建，现有文件在改动前保留其导航契约和回归。

验证编号对应 [验收文档](acceptance.md)。旧导航基线为 71 项，当前导航、设置、配置 / 备份和配额展示契约回归为 177 项；通过这些测试不自动满足下面的 Agent 或后端安全验收。本机配置流程已完成，运行服务与云端边界按 [接入清单](settings-map.md)落到对应任务。

修改现有模块时遵循 [仓库迭代约定](../AGENTS.md)。DATA-04 / UX-01 先完成相关职责拆分：控制器按菜单、弹窗、搜索与快捷键提取，状态按类型、持久化与兼容恢复整理，工作台测试按行为拆开且保持覆盖。新增文件默认 500 行档，超限不能仅登记待办后交付。

## 依赖不等于开放全部功能

RT / DATA 的接口可先被 fixture 验证。CHAT 到 M2 才接入聊天正文；DESK 到 M3 才出现透明模型；Pi 在 M0 是实验、M4 才成为用户 Coding 流程。已完成某个基础任务，不代表整个阶段和所有入口都应开放。

后置范围不混入上述 33 项：NekoPapa 云账号 / 同步、团队共享与权限、多人页面协作、完整 Notion 数据库、通用 UI 自动化、多 Agent 自动委派、插件市场、语音和主动问候。出现真实需求时另写任务与验收，避免用“设置以后能做很多”扩散当前范围。
