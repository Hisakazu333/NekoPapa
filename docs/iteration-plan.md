# 实际迭代计划

更新日期：2026-10-05。基线版本：`0.1.0`。M0–M6 是工作编号，不是已发布版本或日期承诺，当前仍为待开始。已实现范围包括导航专项和设置页；不能把它的索引管理当作 M1 的真实会话存储或 M2 的聊天。

## 现状与优先级

当前导航、收纳、标签、活动侧栏、本地索引及 28 个设置子页与本机配置流程可用，本轮 177 项测试通过，原工作台主内容模板保持原样。按用户当前要求，先完善侧栏、顶部栏及设置页面；暂不连接后端，主页、聊天正文与页面编辑不在本轮范围内。运行契约、应用数据服务、普通 Agent、Pi、桌面角色与成果流程仍是后续阶段。

本轮导航专项完成按人物筛选、各列表显示数量 / 展开、真实父组定位，以及顶部标签查找 / 关闭。验收围绕实际对象：查找只改变索引，打开复用 ID，关闭只关视图，归档用于收纳，删除进入独立回收站且可恢复；全局管理在设置的独立子页，常规选项复用真实偏好，人物偏好不改会话人物。原生与浏览器证据见 [导航闭环](navigation-contract.md)，后续配置归属见 [设置清单](settings-map.md)。

继续导航专项时，先处理用户实际使用暴露的缺口与回归，再按模块进入 M0 / M1。[Agent 产品研究](research/agent-products.md)中的 Notion 分类与列表收纳用于界面；Pi 的会话树、Kimi 的上下文 / 执行记录、Harness 的投影只在真实数据与 Agent 接入时采用，不能用侧栏数组冒充会话文件。项目目录绑定、跨窗口统一 writer、千条索引分页仍属 M1 / M4，当前没有实现。

| 优先级 | 判断标准 | 内容 |
| --- | --- | --- |
| P0 | 不完成就无法可靠使用基本产品 | 运行时、数据与迁移、普通聊天、桌面陪伴、Pi Coding 基本流程 |
| P1 | 核心可用后把工作与成果串起来 | 页面、受控工具、单次工作流、节点重试、导出与正文检索完善 |
| P2 | 有稳定场景后扩展 | 定时、连接器、模板、多平台公开发行；云同步和团队能力另立计划 |

首个日常聊天版本为 M1 + M2，桌面陪伴产品验收须完成 M3，Coding 验收须完成 M4。M0 提前验证 Pi，避免到 Coding 迭代才发现运行环境无法分发。

## 交付顺序与依赖

| 阶段 | 依赖 | 用户可验证的结果 | 核心任务 |
| --- | --- | --- | --- |
| M0 运行时验证 | 当前壳 | 原生包能启动受控 Agent 进程；Pi 最小接入得到真实生命周期证据 | RT-01–RT-04 |
| M1 数据与会话基础 | M0 协议边界 | 当前内容迁移、重启、归档 / 回收站恢复不丢 ID，真正的数据服务可以保存正文 | DATA-01–DATA-05、UX-01–UX-02 |
| M2 普通陪伴 | M0、M1 核心任务 | 配置模型后聊天、停止、重试、重启继续；导航不会打断 | CHAT-01–CHAT-04 |
| M3 桌面陪伴 | M2；正式模型与 SDK 条件 | Live2D 透明窗口、工作区与聊天同步，记忆可确认、改正和删除 | DESK-01–DESK-03、MEM-01–MEM-02 |
| M4 Pi Coding | M0、M1；共享 Run 服务完成 | 选目录完成真实读改验、停止、变更核对和继续同一 Pi 会话 | PI-01–PI-04 |
| M5 页面与工作流 | M2、Run / 授权服务；M3 工作区 | 选资料生成可编辑摘要页面，一个工作流可取消、重试和恢复 | PAGE-01–PAGE-02、FLOW-01–FLOW-03 |
| M6 复用与交付 | M5 | 模板、单个真实连接器、明确周期触发、安装升级与恢复 | AUTO-01–AUTO-02、REL-01–REL-02 |

M4 的技术依赖不包含完整 Live2D 渲染，若模型资源准备较慢，可以在 M2 后推进 Coding；M3 的角色体验仍需单独验收，不能从交付清单消失。暂不分配个人工期；负责人和日期在任务领取及技术验证后登记。

## M0：把运行时风险先验证掉

**目标**：沿用现有 UI，不展开主体页面，实现可测的宿主—Agent 通道和 Pi SDK 实验。

交付：Rust 管理 Node 子进程、版本握手、类型化请求与事件；独立测试目录中的 Pi 最小实例；安装包资源、依赖和 Node 版本验证记录。SDK 首选，官方 RPC 只在兼容问题有证据时作为替代方案，产品接口保持一致。

完成条件：

- 原生 `.app` 在不依赖系统 Node 的启动环境下完成启动、握手、退出；stdout 混入日志、断帧、超大帧、不兼容版本与进程死亡可处理。
- 固定 Pi 版本完成创建 / 恢复、消息、工具、重试、停止与收敛事件检查；确认当前 SDK 的完成判断，不使用 `agent_end` 一刀切成功。
- 锁定或明确阻塞实际 runtime、SDK 制品、资源加载和签名方式，记录源版本与安装后验证。当前 Node 20 开发范围是否调整由此证据决定。
- 所有测试使用独立数据根与项目 fixture，未接触用户原始会话或代码目录。

暂不包括：用户聊天主区、任意 Shell GUI、完整插件市场、模型账号登录体系。

阻塞处理：资源或制品验证失败时保留实验结果和可复现步骤，先解决分发；不能通过要求最终用户全局安装 Node / Pi 来宣称桌面接入已经完成。依赖更新只在实验通过后落实。

## M1：把索引变成真实数据服务

**目标**：数据库、会话身份和已有导航保持一致，建立后续正文与 Run 的保存基础。

交付：平台 appData、SQLite 迁移与唯一 writer、Session / Run / message 模型、托管资源目录、迁移报告、分页查询、快照与事件补取；导航经服务适配保留当前行为。单对象导出 / 导入、备份与独立永久清除管理具备数据闭环。

进入 M2 的基础条件是 DATA-01–DATA-04 和 UX-01 验收通过。DATA-05 / UX-02 可在 M2 起步期间继续；完成前不开放其导出、永久清除和正文检索入口，M1 仍记为进行中。M1 全阶段完成须满足下列全部条件，不能把基础完成写成数据管理全部交付。

完成条件：

- `nekopapa.workspace-shell.v1` 迁移先保留原文，再事务导入；active / archived ID、收藏、顺序、分组、标签与布局可核对；重复迁移不重复创建。
- 旧普通 / 页面条目保持空正文，旧 Coding 标记 unbound；不添加假时间、假 Pi 文件或活跃 Run。
- 接受输入失败时不分发，事件按序去重；重连快照与增量没有缺口或重复；草稿保存失败仍可导出。
- 归档与 Run 生命周期分离，归档中的活跃任务仍可定位；回收站来源与归档来源分开，恢复保留身份；删除拒绝非终态 Run。永久清除拒绝活跃对象，仅清除应用拥有的资源。
- 一致性备份可恢复；DB 与托管文件清理失败可重试；旧库、新库和错误备份都不被静默覆盖。
- 现有导航测试与原生交互回归通过，1,000 个索引不要求加载全部正文才能显示侧栏。
- 按 [仓库迭代约定](../AGENTS.md)落实涉及模块的职责拆分和行数档位，保留原测试覆盖；数据接入不继续扩大现有控制器。

暂不包括：模型回复、页面编辑器、记忆 UI、workflow runner。M1 可使用确定性事件 fixture 验证保存，但不展示成生产运行结果。

回退：writer 切换前失败使用原存储继续；切换后禁止双写，回退通过独立旧备份数据根，不能让旧应用覆写新正文。

## M2：普通陪伴成为每天能用的聊天

**目标**：配置一个真实模型连接后，完成输入、流式、停止、错误、重试和重启继续。

交付：模型配置与宿主凭据引用、自研 Companion Agent、普通消息正文与输入、流式持久化、上下文预算与压缩、草稿及滚动恢复。消息用中性配色；角色头像留在主 UI，完整模型留待 M3。

完成条件：

- 模型连接的可用、无密钥、拒绝认证、限流、超时和离线都有可处理反馈；用户能保存 / 修改配置，不虚构用量或账号权益。
- 至少一次真实模型会话完成输入 / 回复 / 重启继续；确定性 provider fixture 覆盖流式与错误，不把 fixture 当真实调用证据。
- 双击发送不产生重复 Run；停止后状态收敛，部分回复保留；重试关联原输入，新 Run 可追踪，不重复追加用户消息。
- 最新一轮重新生成保留旧答案修订；当前上下文不混入多次答案或失败片段，较早位置的分支重写后置。
- 关闭 / 打开标签、换侧栏分类、归档 / 恢复和重启不会把同一会话复制，也不会因为 UI 卸载停止模型。
- 模型上下文只包含当前普通会话、角色、选定资料；长对话压缩不删除可读历史。

暂不包括：语音、主动打扰、多 Agent 委派、自动长期记忆写入和任意 OS 工具。

回退：模型连接失败或 Agent 不可用时，历史与导航仍可读取并导出；停止新的模型请求，不抹掉已提交输入。

## M3：透明桌面角色和可管理记忆

**目标**：落实本产品的桌面陪伴特点，三种窗口读取同一状态。

交付：真实 Live2D 模型加载与透明窗口、拖动 / 隐藏 / 恢复、角色反馈映射、独立 Agent 工作区、退出协调；记忆的手动确认、编辑、删除与上下文引用来源。

完成条件：

- macOS 原生窗口透明且不显示主 UI 背景，模型与交互区域可用，位置和显示偏好可恢复；不是把人物 PNG 当成 Live2D 交付。
- 头像点击、模型聊天入口和工作区返回均定位已有 Session；连续点击不新建多份会话。
- 主窗口、工作区和角色的运行状态来自同一 Run；两处确认同一操作只执行一次，窗口重建可重订阅。
- 最小化、隐藏模型、关闭工作区不会停止 Run；明确退出按约定停止、保存并结束进程。
- 记忆确认后可见、可改正、可删除；来源明确，删除后的新请求不再检索，聊天压缩不会偷偷成为记忆。
- 正式 SDK / 模型许可、资源来源和分发方案已确认；加载失败保留头像和聊天入口。

可以延期：语音口型、丰富表情动作、主动问候和复杂角色切换。模型许可或文件缺失时，完成窗口与降级路径并记录阻塞，Live2D 验收保持未完成。

## M4：Pi Coding 完成真实项目任务

**目标**：在一个用户明确选择的本地项目内完成读取、修改、验证并继续同一会话。

交付：项目目录绑定、Pi Adapter 的持久实例管理、生命周期与授权、原文件恢复与索引对账、长输出、文件差异和验证记录。保持普通会话与 Coding 会话隔离。

完成条件：

- 对独立测试仓库完成一次真实“读取说明 → 修改文件 → 执行测试 → 核对差异”；命令 exit code、测试范围与实际内容一致。
- 同一项目两个写 Run 按约定串行，两个项目各自 cwd / 模型 / 上下文不串；不存在路径不能默默换成宿主目录。
- 首次输入和重试有稳定映射，崩溃分别覆盖“DB 已提交 / Pi 未确认”和“Pi 已提交 / DB 投影未写”；不自动重放结果未知的操作。
- 读取包含分支、压缩、上下文编辑的样例后仍按 Pi 活动分支继续；投影重建不改普通记忆和产品归属。
- 停止等待 Pi idle，关闭标签不 dispose；后台完成不抢焦点。修改过的代码在停止后保持真实状态，无虚构回滚。
- 改分组不改目录；改 cwd 创建新会话。导出明确原历史 / 当前分支范围，不覆盖外部 Pi 原件。

后置：完整 IDE、通用 Git 图谱、自动开 PR、多 Agent 开发、远程工作区和完整树浏览器。基本分支读取正确性属于本轮必需，树形 UI 可以以后增加。

## M5：保存成果并跑一个普通工作流

**目标**：从用户选定的本地资料生成摘要，保存为可编辑页面，结果能再次打开。

交付：最小 Markdown 页面、版本与来源、资料引用选择、普通工具注册表、授权、节点输入输出、取消与失败重试。工作区同步真实步骤。

首个固定流程：选择有限的文本资料 → 读取 → 自研普通 Agent 整理摘要 → 创建页面 → 从会话打开页面继续编辑。输入、执行、页面版本和来源形成完整链条。

从明确的普通 Session 启动，一次工作流对应一个 Run，模型节点复用执行服务，不重新创建聊天 Run。

完成条件：

- 页面使用独立 ID；刷新、标签关闭 / 重开和重启保留正文；两个视图冲突返回可处理的版本提示。
- 资料有路径 / 资源 ID、版本或内容 hash；文件已改变时重新确认输入，不把旧引用当当前内容。
- 普通模式仅调用注册工具；需要确认的写操作在两个窗口一致，未确认或已过期的动作不执行。
- 重试节点有 attempt 与幂等键；已经创建页面的步骤不重复创建；未知外部结果先核对。
- 部分完成、失败、停止和崩溃都保留可读记录；恢复只重试允许的节点，定义修改不改变旧 Run。

暂不包括：可视化 DAG 编辑器、通用 RPA、完整富文本 / 数据库、自动互联网资料采集。先把一个真实流程交付，再依据使用反馈增加工具。

## M6：复用、明确触发和发行验证

**目标**：在已有流程上增加版本化模板与用户明确配置的周期运行，接入一个实际需要的连接器。

交付：模板复制、日程和时区、启停、运行历史、去重与错过记录；连接器配置 / 断开与错误；原生发行候选、升级备份与恢复演练。连接器在场景确定后选择，不预先把常见品牌都画为已连接。

完成条件：

- 同一 occurrence 不启动两次；上一轮未结束时记录 skipped / busy，按约定不叠加；暂停只停止新触发。
- 触发器绑定目标普通 Session，目标归档 / 清除或已有活跃 Run 时不执行，并记录原因；不自动新建会话或解除归档。
- 应用关闭或系统休眠时不能本地执行；错过的触发记录 skipped，不自动补做有副作用的任务。下一次时间按用户选择的时区计算，覆盖 DST 与时钟变化。
- 复制模板只复制定义与可访问资源引用，不复制 Run、未决授权、凭据或活动记录。
- 一个真实连接器完成授权配置、查询或写入、结果保存、断开和失败恢复；没有场景和凭据时保持待验收。
- 原生候选包在声明支持的平台验证安装、首次启动、无系统 Node、升级 / 回退和数据恢复；公开发行另外核验签名与公证。

每轮都要有可安装候选与对应验证；M6 是完善公开分发和复用流程，不是把之前的原生验证拖到最后。Windows / Linux 可单独开交付阶段，未经验证不列为支持平台。

## 每轮结束必须留下什么

| 记录 | 必须包含 |
| --- | --- |
| 任务结果 | 完成任务 ID、代码位置、未完成项和实际限制 |
| 验证 | 命令 / 场景、fixture 或原生平台、通过与失败证据 |
| 数据变化 | schema / 协议 / Pi 版本、迁移和备份结果 |
| 用户流程 | 从入口到真实保存结果、错误和恢复的演示 |
| 文档更新 | README 当前功能、任务状态、必要的导航职责和资源说明 |
| 代码结构 | 修改模块的职责、行数档位与实际拆分结果；保留等价测试覆盖 |

不能只按“文件已经创建”标记完成。主内容区开发从 M2 起按明确功能接入；M0 / M1 仍以已有侧栏与顶部栏为回归边界，不趁数据重构重做整个页面。

任务分解见 [开发清单](iteration-backlog.md)，逐场景验收见 [验收与交付](acceptance.md)。
