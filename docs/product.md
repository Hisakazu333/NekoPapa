# NekoPapa 产品定义

更新日期：2026-10-04。本文记录既定产品方向和下一阶段目标，当前已实现范围见 [README](../README.md)。

## 产品要解决的问题

让用户有一个可持续交流的桌面陪伴角色，也能在需要时进入 Coding 会话处理代码项目。交流、执行与成果有明确归属，重启后可以继续，多个窗口不会把一件事变成多份会话。

最先服务单个用户的本地桌面使用：聊日常、查找之前聊过的事情、打开项目继续工作，以及把有用结果保存成页面。团队协作、完整 Notion 数据库、插件市场和云端同步不进入首个可用版本。

## 已确定的方向

| 方向 | 产品约定 |
| --- | --- |
| 客户端 | 沿用 TypeScript + Tauri；不因研究竞品更换现有客户端框架 |
| 普通模式 | 自研陪伴 Agent；先完成聊天，再加入记忆、受控工具与工作流 |
| Coding 模式 | 集成 Pi Coding Agent 并二次开发；产品层负责目录绑定、导航、授权、展示与恢复 |
| 导航 | 保留双层侧栏和顶部多标签；工作台收纳角色、收藏与最近访问，对话按活动分组，空间 / 项目各自管理目录，标签打开真实对象 |
| 视觉 | 黑白灰、轻量边界、紧凑行距、统一图标；主聊天不用微信绿色配色 |
| 角色 | 五位正式人物可切换，`lumia` 是白羽澪兼容保留的内部 ID；选择偏好与会话角色分别保存，已有会话不因切换而换人 |
| 桌面形态 | 主窗口、透明 Live2D 陪伴窗口、独立 Agent 工作区，共用同一状态源 |
| 内容生命周期 | 会话优先归档与恢复，物理清除独立设计；项目文件不随分组归档或移除而删除 |

## 核心用户流程

| 流程 | 用户操作 | 必须得到的结果 | 交付阶段 |
| --- | --- | --- | --- |
| 继续陪伴 | 选择人物，点击独立继续入口或已有普通会话，发送消息 | 复用该人物的会话 ID；已有会话保留原角色；流式回复，重启可读且可继续 | M2 |
| 管理会话 | 改名、移动、收藏、关闭标签、归档、恢复 | 同一正文保留；每个动作只改变自己的状态 | M1 / M2 |
| 桌面陪伴 | 显示模型、拖动或隐藏；点击简短入口 | 模型透明显示在桌面；定位已有会话；隐藏不取消运行 | M3 |
| 执行 Coding | 绑定项目目录，新建 Coding 会话，请求修改与验证 | 真实 Pi 运行、可核对文件变更、真实命令结果、停止与恢复 | M4 |
| 保存成果 | 把某段结果保存为页面，再从标签打开编辑 | 页面有独立 ID 和来源；重启保留正文，修改有冲突反馈 | M5 |
| 普通工作流 | 选定资料，整理摘要，保存页面 | 步骤与真实输入输出对应；失败可查；重试不重复写成果 | M5 |
| 周期运行 | 明确创建时间规则或连接器任务 | 定义与运行记录分开；可暂停；休眠错过有记录与处理规则 | M6 |

模型配置、首次目录授权、输入、执行、停止、失败、重试、重启与成果重新打开属于同一条流程的完成条件。只接上模型输出或画出任务卡不算交付。

## 对象关系

| 对象 | 身份与用途 | 关键关系 |
| --- | --- | --- |
| 本地工作台 | 一份用户数据根与设置 | 第一版只有一个；未来账号不自动取代本地数据身份 |
| 空间 | 普通对话与页面的收纳组 | 移动内容保留内容 ID |
| 项目 | Coding 内容及相关资料的收纳组 | 独立绑定真实目录；目录不作为会话 ID |
| 会话 Session | 一段可继续的普通或 Coding 交流 | 模式创建后固定，拥有多次 Run；角色 ID 可关联但不代替会话 ID |
| 运行 Run | 一次被接受的输入或工作流执行 | 有独立状态、输入快照、输出、失败与授权记录 |
| 页面 Artifact | 可编辑的长期成果 | 来源指向会话、运行及消息；修改页面不改原聊天 |
| 记忆 Memory | 用户确认的偏好或事实 | 与聊天压缩摘要分开，可查看、改正、删除 |
| 工作流定义 | 一份版本化步骤与触发配置 | 每次触发产生独立 Run，使用定义快照 |
| 标签 View | 某个内容对象的打开视图 | 关闭保留内容；草稿、滚动属于视图状态 |

“收藏”用于常用访问，“置顶”用于活动侧栏关注。二者不相互覆盖。最近访问由打开行为产生，最近活动由真实消息或执行事件产生。

普通工作流在明确选定的普通 Session 中运行；每次执行只有一个产品 Run，节点不另建聊天 Run。周期触发配置保存目标 Session，目标已归档、被清除或仍有活跃 Run 时记录跳过 / 需要处理，不自动恢复归档或新建替代会话。

## 两种模式

普通模式输入由角色配置、当前会话、明确选定资料及有效记忆组成。最初只有聊天，无任意 Shell 执行；工具按实际场景注册，工作流使用同一工具执行服务。

Coding 模式由 Pi 管理模型上下文、工具循环、分支与压缩。NekoPapa 不重新实现这些核心能力。会话绑定项目目录，界面显示读取、修改、命令、结果与验证记录。普通模式的私人记忆不会自动注入 Coding；引用个人资料需显式选择。

模型配置可以共用入口，但每次运行记录实际 provider、model 和配置版本。切换标签、分组或角色不把普通会话升级为 Coding。要使用另一种模式，创建另一条会话，可附带选定摘要并记录来源。

## 导航与三个窗口

当前按钮行为以 [导航矩阵](navigation-map.md)为准。后续功能必须接入现有真实内容 ID，不通过系统占位 ID 制造空标签。

| 区域 | 负责什么 | 后续接入规则 |
| --- | --- | --- |
| 外侧窄栏 | 切换四类索引；「更多功能」与固定产品入口；底部布局和账号 | 分类保留当前内容；功能预设用弹窗说明用途和状态，接入后调用对应服务，不生成空标签 |
| 内侧栏 | 当前索引、角色、活动、分组、收藏与最近访问 | 搜索分页、列表数量与折叠控制密度；同一会话只是一份数据 |
| 顶部栏 | 打开、切换、排序和关闭内容视图 | 接入草稿及滚动恢复，运行提示来自 Run；关闭后台标签不抢焦点 |
| 主窗口 | 会话、页面及 Coding 内容 | 普通消息左右排列；Coding 长输出和变更按需展开；入口随迭代接入 |
| Live2D 窗口 | 模型与轻量反馈 | 显示、隐藏、拖动、交互区域与透明区域分别处理，模型故障可退回头像 |
| Agent 工作区 | 当前运行、步骤、待确认与返回会话 | 一份 Run 的另一视图；不能建立自己的执行队列或再次启动同一操作 |

主窗口最小化不停止运行。关闭主窗口与退出应用分别处理：计划以“仍有陪伴窗口、工作区或运行时保留宿主；全部闲置窗口关闭则退出”为首版规则，并在 M3 验证原生行为。明确退出时由宿主停止接收新输入、取消或结束现有操作、落盘并退出；不宣称应用退出后本地任务还在执行。

当前按用户要求保留产品独有的功能预设，默认固定桌面陪伴、记忆、工作流，所有功能可从「更多功能」查看并调整固定状态。预设的说明文字是产品定义，实际 Live2D、记忆与工作流仍按原阶段交付；固定或打开说明不会创建会话。具体入口行为见 [功能预设](feature-presets.md)。

## 生命周期语义

| 动作 | 实际改变 | 用户反馈 |
| --- | --- | --- |
| 关闭标签 | 视图集合 | 内容仍可从侧栏打开；运行继续 |
| 归档会话或组 | 收纳状态及打开视图 | 可恢复；运行不取消，有未结束 Run 时仍能从活动 / 工作区定位 |
| 停止 | 指定 Run 的执行状态 | 先显示停止中，收到停止结果后显示已停止；已发生的文件修改不自动回滚 |
| 恢复归档 | 内容归属、顺序与常用关系 | 使用原 ID；不自动发送历史输入或启动模型 |
| 永久清除 | 指定应用记录及关联资源 | 独立于归档，显示范围；运行中拒绝；不清除用户项目目录 |
| 清除记忆 | 后续可检索记忆 | 后续请求不再引用；已显示消息和已发出的请求保持原记录 |

归档期间收到新事件不会隐式取消用户归档。待确认或失败仍可通过“运行中 / 需要处理”的入口打开只读归档会话和 Run，常用列表保持归档。具体实现见 [会话管理](session-storage.md)。这部分是接入真实执行后的目标，当前导航壳尚无运行行为。

## 首版范围与延期项

首个日常可用闭环为 M1 + M2；桌面陪伴的产品验收须完成 M3。Coding 的完成条件为 M4，普通工具工作流为 M5。各阶段可独立验收，只有验证过的能力进入 README 可用列表。

后置范围包括多人协作、跨设备消息接续、云端后台执行、完整数据库与表格系统、多 Agent 自动委派、插件市场和任意 UI 自动化。语音、主动问候、自动记忆推荐可在稳定文字陪伴之后按反馈安排。保留扩展接口不等于先开发这些能力。

永久清除先针对应用拥有的数据建立明确规则；用户项目目录、Git 提交和外部连接器数据属于独立对象，不提供一个“删除项目”动作混合处理。

## 产品验收原则

结果来自真实模型、工具或用户保存；缺少活动时间、正文、额度与登录信息时明确显示实际状态。失败、取消、冲突与恢复能通过界面处理，不能要求用户编辑内部 JSON 或数据库。侧栏密度、顶部标签、键盘与原生窗口行为沿用现有验收，并在有真实正文后再次检查。

用户流程拆解见 [迭代计划](iteration-plan.md)，对应故障和边界场景见 [验收文档](acceptance.md)。
