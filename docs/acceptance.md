## 验证层次和环境

| 层次 | 用途 | 不能替代什么 |
| --- | --- | --- |
| 领域 / 契约测试 | 身份、状态机、事务、序号、错误、迁移与幂等 | 不能证明系统窗口、正式模型或安装包可用 |
| 确定性 Agent / provider fixture | 流式、乱序、重试、取消、崩溃边界 | 不能证明真实模型接口或工具完成工作 |
| 浏览器交互 | 侧栏、标签、输入、页面、焦点和布局 | 不能证明透明窗口、Keychain、进程和原生分发 |
| Tauri 原生与安装包 | 宿主、凭据、窗口、Node / Pi 资源、退出与重启 | 不能替代上游接口和真实用户流程验证 |
| 真实服务 / 独立项目 | 普通模型、Pi 读改验、连接器和成果 | 不允许把 fixture 数据当生产输出 |

全程使用独立 appData 和一次性 fixture 项目，不把测试写入用户预览、安装版数据或真实代码库。每份报告记录代码版本、schema、协议、SDK、平台 / 架构、数据根类别、场景、通过 / 失败及证据路径，不记录密钥。

## A-NAV-01：已有导航不回退

对应 UX-01 / UX-02，接入正文及 Agent 后每轮抽查。

- 外层四种分类只切换内侧索引，当前标签、正文、草稿、滚动与 Run 保留；搜索分组只定位，搜索内容复用同 ID。
- 角色入口继续原普通 Session，没有会话时按现有创建流程；角色 ID 不作为 Session ID。
- 分组改名 / 展开 / 折叠不新建标签；移动保留模式、正文与目录绑定。
- 标签关闭 / 重开、关闭右侧 / 其他、中键、溢出列表、拖动排序和内容导航历史按实际对象工作；没有对象时不重建假记录。
- 收藏、置顶、最近访问、真实活动时间与未读相互独立；活动筛选和关闭视图不变成取消。
- 归档、删除、回收站恢复、损坏数据提示、布局、菜单方向键 / Escape / 焦点返回及拖动键盘替代保留。
- 设置分类、搜索、独立历史和关闭返回不改变内容 ID、标签与会话人物；保存失败可见且可重试。隐藏工作台侧栏后，设置导航仍可访问；已打开设置时，新建和标签快捷键不操作背后的内容。
- 760 × 520 窗口和最窄 196px 侧栏有正确滚动与固定底部入口，顶部标签没有遮住原生窗口按钮；减少动态效果仍有效。

现有测试因数据服务重构需迁移时，列出旧断言到新验证的对应关系，不通过删除旧测试来消除回归。

## A-RT-01：进程、协议、事件与重连

对应 RT-01 / RT-03 / DATA-03。

| 注入条件 | 预期结果 |
| --- | --- |
| Agent 未启动 / 缺失资源 / 版本不匹配 | 明确不可用错误，导航和历史仍可读 |
| stdout 日志、非法 JSON、断帧、超大消息 | 受控拒绝或停止连接，不执行字符串内容，不把错误当 Run 完成 |
| 同 requestId 重复提交 | 返回原接受 / 拒绝结果，无第二条输入或 Run |
| 源事件重复、序号乱序、缺口 | 宿主去重或拒绝；客户端补取，不回退到旧快照 |
| 快照读取与持续流式同时发生 | 从 asOfSeq 之后接事件，没有消息重复或跳过 |
| UI 重建 / 窗口关闭 / 切分类 | Run 保持原 ID，重订阅补快照，不新启动进程或 Run |
| Node 中途死亡 | 非终态 Run 进入 interrupted，已提交部分保留，用户可处理 |

内存未提交的消息不得显示“已保存”。测量长输出与积压时的上限处理，避免进程读写相互阻塞。

## A-RT-02：Pi SDK 接入实验

对应 RT-02 / RT-04。使用固定候选版本、独立 agentDir、sessionDir 与 cwd。

覆盖创建 / 恢复 / 实例释放、首次 prompt、模型错误、工具失败、自动重试、停止、无模型请求的扩展命令，以及重绑事件订阅。验证 `message_end`、`agent_end`、`agent_settled` 和 `prompt()` resolve / reject 的实际关系；不能用一个事件对所有情况判成功。

确认切标签不调用 dispose，abort 后回到 idle，插件 / resource loader 与固定资源可加载；运行环境满足 SDK 的 Node 要求。测试包含一个真实模型和工具调用，确定性 fixture 单独报告。

## A-DATA-01：旧索引迁移

对应 DATA-04。

| 样例 | 必须保留 / 处理 |
| --- | --- |
| 完整 v1，active + archive + trash + 手动排序 | 所有合法内容 ID、归属、收藏位置、标签、布局、归档 / 回收站批次及来源状态 |
| 只有首页或旧系统 / 分组占位 | 清理占位，首页可用，不制造空 Session |

| 原有 recovery / 重复迁移 / 迁移中断 | 备份不覆盖，source hash 去重，事务失败可再次启动 |
| 旧 Coding 无 cwd / 旧活动无真实 Run | unbound / 历史提示，无假 Pi header、假活跃状态或迁移时间回复 |
| 浏览器 JSON 显式导入 | 独立来源与冲突规则，不自动覆盖原生数据 |

## A-DATA-02：保存、崩溃和运行状态

对应 DATA-01–DATA-03 / CHAT-03。

在输入事务前后、outbox dispatch 前后、首个 delta、partial 提交、message final 和 Run 终态提交处分别注入失败。拒绝的输入不调用模型；已接受输入重启后可见，回复前缀不变成完整成功答案。

覆盖磁盘满、只读数据根、DB busy / 写失败、进程死亡和显式退出超时。错误可重试或导出；不能因为“恢复”而删除历史。两个窗口收到 final 只追加 / 收敛一次；旧事件不能覆盖新状态。

状态机逐条验证 accepted / preparing / running / waiting / cancelling / completed / failed / cancelled / interrupted；等待必须有 reason，终态不可被迟到 delta 改回 running。取消与自然完成竞争以提交的实际结果处理，不伪造副作用回滚。

## A-DATA-03：归档、删除与清除

对应 DATA-03 / DATA-05。

- 普通会话、Coding、页面和分组反复归档 / 恢复，ID、排序、收藏、正文与绑定不变；恢复当前 batch 不影响后来的独立归档。
- 活跃 Run 所属内容归档后，运行 / 需要处理区及工作区仍可定位、停止、确认；人工归档不被新回复自动取消。
- 关闭归档视图不恢复常用列表，继续发送需恢复；恢复不自动运行历史输入。
- 删除确认、取消、撤销、重载与回收站恢复闭环；从归档删除的对象恢复至同一归档，常用来源恢复原 ID、顺序与收藏，管理恢复不替换当前内容。
- 删除分组只影响当前成员；关闭恢复 / 历史不能重新打开删除对象；拒绝非终态 Run；损坏批次保留原件与有效成员。
- 永久清除仅针对回收站对象，拒绝非终态 Run，明确范围；只删除应用拥有的文件；引用同一附件的其他对象、独立页面和记忆保留。
- DB 清理标记已提交而文件删除失败，重启能重试；外部 Pi 原件、项目目录、Git 文件保持原状。

永久清除验收只用一次性数据，不对用户现有归档做删除测试。

## A-DATA-04：导出、备份与导入

对应 DATA-05 / CHAT-04 / PI-04。

可读分享、可恢复单对象包、工作台备份和诊断包分别检查范围。分享默认只选定分支 / 消息，不混入隐藏分支、其他 Session、凭据或全局日志；完整备份明确包含原历史。

DB 使用一致性备份而非单独复制主文件。完整工作台备份验证冻结新写命令、等待运行结束或用户停止、Pi idle / 普通事件落盘、持续写锁内复制与释放；等待时取消备份可恢复正常操作。恢复到全新数据根，核对普通消息、Coding 原文件、产品元数据、资源引用和未完成 Run 标记。不能只证明 ZIP 可以解压。

导入覆盖旧 / 新格式、校验失败、缺附件、同 ID、超大文件、路径穿越和符号链接。冲突不覆盖原对象；新映射和来源可追踪。导出路径无权限 / 磁盘满时不提示成功，不自动归档或清除原数据。

## A-CHAT-01：真实普通陪伴

对应 CHAT-01 / CHAT-02。

从未配置开始，保存一个模型连接，经宿主读取凭据，发送真实消息，流式完成，关闭应用再打开继续同一 Session。检查角色语气、当前会话隔离、选定资料来源、布局与草稿恢复。

认证失败、限流、离线、无模型、凭据读取失败分别给可处理错误，输入仍在。凭据不进入 DOM、localStorage、会话日志或导出。更改配置影响下一次 Run，进行中 Run 保持自己的快照。

## A-CHAT-02：停止、失败和重试

对应 CHAT-03。

双击发送、流中停止、final 前后停止、回复中断与最新一轮重新生成均有明确结果。重试新建关联 Run，不重复用户消息；旧回复仍可读，新答案完成后才切换当前修订。检查后续请求采用的答案，失败 / 中断片段与旧修订不混入当前上下文。首版生成中输入不隐式排队，较早位置不提供尚未实现的分支重写动作。

后台回复不抢当前标签；关闭标签 / 隐藏窗口不停止。进程强退后显示 interrupted，点击恢复仅准备继续，用户重试才再次请求。模型返回的部分文本不直接当完整答案。

## A-CHAT-03：上下文和记忆

对应 CHAT-04 / MEM-01 / MEM-02。

准备两个普通 Session、一个 Coding 和不同 scope 的记忆。实际检查 provider 请求或可审计的组装记录：仅当前会话、选定资料、角色与有效记忆入上下文；Coding 默认无私人记忆。

覆盖长对话预算与压缩、压缩失败、删除 / 修改记忆、重复建议与用户未确认。可阅读消息不因压缩删除；确认记录可查看，删除之后的新请求不引用，已发请求及历史保持原样。

## A-DESK-01：真实 Live2D

对应 DESK-01，仅原生环境可通过。

检查实际 SDK / 模型加载、动态渲染、背景透明、位置恢复、拖动、隐藏 / 显示、交互命中区域及减少动态效果。模型失败保留聊天入口；重复点击角色复用 Session。

报告注明模型 / SDK 来源和许可、设备与图形环境。仅有 PNG、浏览器透明背景或概念图不算通过原生 Live2D 验收。

## A-DESK-02：三个窗口和退出

对应 DESK-02 / DESK-03。

同时打开主窗口、角色与工作区，核对同一 Run 的状态和步骤；两窗口对同一 approval 先后确认，只执行一次。关闭 / 重建工作区补快照，主窗口最小化与隐藏模型不中断。

检查关闭主窗口、最后一个闲置窗口和明确退出的分别行为。退出过程中停止接收新请求，取消 / 落盘 / 进程结束可核对；超时记 interrupted，重启提供真实恢复。应用已经退出时不能显示本地任务仍运行。

## A-PI-01：真实项目读改验

对应 PI-01 / PI-03。

使用独立小仓库，预留一处可验证的 Bug 与测试，同时保留一份已有未提交改动。Pi 读取项目说明、修复 Bug、运行测试、显示真实 exit code 与差异。

覆盖两个项目的 cwd 与上下文隔离、同项目并发写限制、目录丢失、符号链接范围、未授权操作、扩展加载策略。收纳移动不改变绑定，改 cwd 创建新会话，普通模式不能调用 Coding 工具。

## A-PI-02：Pi 文件和应用库对账

对应 PI-02。

固定样例包含线性历史、至少两条分支、压缩、上下文编辑、工具错误与 SDK 支持的旧格式。打开、继续、切分支和重建投影与 Pi 读取结果一致，不把全部分支拼接成当前上下文。

分别注入 DB 已有 request / Pi 未确认、Pi 已写 / DB 未更新、文件不存在、格式过新和请求关联缺失。未确认执行结果不自动重发；原文件不被空文件覆盖，元数据 / 收藏 / 归档不会随着重建丢失。

## A-PI-03：差异、授权和停止

对应 PI-03 / PI-04。

单工具结束不标整轮完成，自动重试和队列后续仍归属于正确 Run。停止后等待 idle，展示实际已经发生的文件修改；命令或工具结果未知时给核对入口。

diff 以请求前后与已有脏改动范围为依据，说明无法明确归因的变化；不能把整个工作区的历史改动全部称为 Agent 新增。大输出截断有标记且原结果可分页读取，测试失败不被成功自然语言覆盖。

## A-PAGE-01：成果身份与编辑

对应 PAGE-01 / PAGE-02。

从选定消息保存页面，修改正文，关闭标签、刷新和重启再打开。检查独立 ID、版本、来源与导出。两个视图基于同一 revision 同时保存，后者提示冲突而非静默覆盖。

归档来源会话不归档页面；永久清除来源后页面保留并提示来源已清除。保存失败保留未保存草稿和可恢复入口。

## A-FLOW-01：一个完整普通工作流

对应 FLOW-01 / FLOW-02。

选定普通 Session 和两份独立文本资料，核对读取内容和 hash，通过真实模型整理摘要，保存页面并重新打开编辑。检查一份工作流只创建一个产品 Run，模型节点不额外追加用户输入。节点状态、输入、输出和页面来源与实际执行一致。普通模式仅使用注册工具，未知工具、无权资料和未确认写入拒绝执行。

## A-FLOW-02：节点重试与副作用

对应 FLOW-01 / FLOW-03 / AUTO-02。

在读取后、模型后、写页面前、写成功但响应丢失时注入失败；重试允许节点，页面不重复创建。两个窗口确认同一输入 hash 的步骤只能执行一次；参数改变后的旧确认无效。

取消、进程死亡、定义版本修改、资料改变、连接器限流和外部结果不明均有持久记录。确定性 fixture 与真实服务分开报告；外部写入未知时先核对，不自动重做。

## A-AUTO-01：周期和复用

对应 AUTO-01 / AUTO-02。

检查重复 occurrence、上一轮未完、目标 Session 归档 / 清除或其他 Run 占用、暂停 / 恢复、应用关闭、休眠、重启、系统时钟与 DST。错过触发记录 skipped，默认不补做；归档不会自动解除，暂停不删除历史；Run 使用当次定义快照。

复制模板不复制 Run、授权和密钥。真实连接器有配置、操作、断开、过期和错误处理，只有模拟接口时保持待验收。

## A-REL-01：原生包与升级

RT-04 起每轮执行适用部分，REL-01 完成公开发行范围。

- 从安装包启动，验证 bundled Node、JS / Pi 资源、凭据和数据路径；进程不能依赖开发终端 PATH。
- 在新数据根与旧版本数据样例上分别验证首次运行、升级、失败恢复和显式退出；关闭后无遗留 Agent 子进程。
- 版本 manifest 记录 app / schema / protocol / runtime / SDK，资源 hash、依赖和第三方许可齐备。
- macOS 本地开发签名与公开发行签名 / 公证分别报告，不能把 adhoc 验证当发行验收。
- Windows / Linux 必须在相应原生包验证后列为支持；浏览器和 macOS 测试不代替这些平台。

## A-SCALE-01：规模与恢复测量

对应 UX-02 / REL-02。计划样例为 1,000 个内容索引、100,000 条普通消息、20 个 Pi 会话（含分支和压缩）及一个大工具输出。它们是合成基线，不是当前产品已测容量。

记录列表首屏、全文查询、分页、投影重建、备份恢复的耗时和峰值内存，以及平台 / 硬件 / 样例大小。侧栏首屏不全量扫所有 transcript，打开会话不加载所有大输出，客户端事件积压有界。中文语料覆盖“睡前聊聊”“界面细节”等完整词及子串，报告实际匹配行为。

第一次测量后制定可重复的性能阈值，不能无依据写毫秒级承诺。恢复核对内容数、ID、来源和状态，性能检查不能牺牲数据正确性。

## 执行和交付记录

当前已存在的命令：

```bash
npm run check
npm run test
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
npm run desktop:build -- --debug
```
