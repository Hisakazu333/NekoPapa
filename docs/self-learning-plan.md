# 个人自学工作台规划

规划日期：2026-11-08。首批用户为个人学习者，场景限定在大学课程、编程和专业知识自学。
本文定义目标行为与开发顺序，不表示学习空间、资料检索、练习批改或复习调度已经实现。
当前代码基线与运行限制见 [README](../README.md)，后端设计依据见 [DeepTutor 源码对照](deeptutor-integration.md)。

## 产品定位与范围

NekoPapa 的学习方向是**有同伴陪着学的个人学习工作台**。
用户带着一门课、一个问题或一个项目进入，能够从资料中理解知识，通过自己的作答检查理解，再留下可继续使用的笔记和成果。
同伴负责陪伴、提问节奏和表达风格；知识依据来自材料、可靠工具与可追溯反馈。
五位官方同伴沿用现有联系人 ID 和设定，不额外编造学科资历，也不把换同伴当作换知识库。

核心由 NekoPapa 自己实现，参考 DeepTutor 当前的资料证据、Mastery 教学、作答存储与运行恢复设计。
联系人负责人格与连续对话；检索、讲解、出题、评价是后台职责，同一个同伴可调用多种已授权能力。
职责不同不代表每次都要启动多个 Agent，也不代表五位同伴必须分别绑定五门学科。
可见群聊需独立定义发言、上下文、资料与取消规则，不能把内部并行 worker 直接变成群聊成员。

第一版提供单人、本机优先的学习流程，自定义模型路径不强制登录官方账号。
优先交付资料解释、短练习与笔记之间的闭环，避免把聊天、阅读器、题库和任务面板各做成孤立入口。
暂缓教师班级、成绩管理、LMS 对接、排行榜、自动生成整门课程和无人监督的研究流水线。
Live2D 可以后续增强陪伴体验，不能成为文字学习流程上线的前置依赖。

## 三个首要场景

### 大学课程：读懂一章并能独立解题

以线性代数为例，用户建立“理解特征值并完成课后题”的目标，加入讲义中对应章节。
先用两三道诊断题了解先修知识，允许跳过；诊断不足时记录“尚无足够证据”，不能直接判定掌握程度。
同伴依据选定段落解释概念，用户可切换直观例子、公式推导和逐步提示，并在右侧核对讲义原文。
用户先提交自己的推导，再逐级获取提示；反馈区分计算错误、概念误解和依据不足，形成可编辑的错因记录。
完成标准是能解释关键概念并独立完成一题相近变式，答案与证据随学习记录保存。

### 编程：理解代码并完成可验证的小项目

以“掌握 Python 文件读取并写一个日志统计器”为例，先阅读指定文档、代码或错误输出。
第一阶段可解释代码、预测运行结果和讨论方案；未接入执行器时明确标记“未运行”，不显示测试通过。
项目执行阶段必须绑定真实项目目录，展示文件改动、命令、退出码和实际输出，并让用户解释修改原因。
同伴先提供问题定位和最小提示，用户可选择查看示例；复制完整答案不自动记作独立完成。
完成标准是用户提交自己的实现，通过明确测试，并能解释至少一个边界情况；运行能力依赖 Coding 执行层与宿主验收。

### 专业知识：围绕问题形成有依据的判断

以“理解数据库事务隔离并选择业务方案”为例，用户指定目标问题与可靠资料范围。
系统提取概念与资料间的分歧，逐项给出可打开的章节或段落，保留发布日期及适用版本。
用户通过案例比较作答，同伴按事先可见的评价点反馈；开放问题保留不确定性，不把唯一措辞当作标准答案。
最终保存结论、条件、反例和出处；遇到时效性资料时提示核对版本，不能以旧材料冒充当前规则。
完成标准是一份用户确认过、引用可定位、适用边界明确的知识笔记。

## 一次学习的完整循环

1. **定目标与诊断**：用户写出希望能做什么、当前基础和可用时间；系统提出可修改的小目标。
2. **加入资料与找依据**：确认解析结果和使用范围，先找到支撑回答的材料，再生成解释。
3. **分层理解**：支持先概览、再例子、再推导；“继续解释”和“给我提示”是不同操作。
4. **主动练习与反馈**：先让用户回忆、作答或操作，再展示反馈；答案揭示前不泄露解答。
5. **整理错因与复习**：保留原始作答和提示使用情况，将需要再练的概念加入可调整的复习安排。
6. **沉淀笔记与项目**：用户确认后保存可编辑内容，能从笔记返回原资料、练习和聊天。

每一步都可暂停，重开后回到原学习空间；完成一轮解释不等于完成整个目标。
用户可直接提问，也可主动进入练习，不强迫每次聊天都走完固定教学流程。
复习任务允许推迟、跳过、修改和删除；未做的练习不被模型自动代答或补为完成。

## 界面如何组织

沿用 BoardUI Chat Starter 的视觉基础与现有设置、账号和联系人入口。
当前侧栏“联系人”打开主工作区的紧凑联系人列表与连续聊天，五位同伴、搜索和顶部新增均在页内；本规划不把人物列表铺回侧栏。
现有工作台首页使用猫图标、衬线问候、大输入区和快捷提示，右侧可拖动辅助区目前展示聊天历史；资料 / 练习 / 笔记是后续扩展，不是现有执行能力。
后续新增“学习空间”入口时，先与现有导航契约统一；课程、项目和专题是空间的内容类型，不复制三套聊天状态。

学习空间头部显示名称、当前目标和绑定同伴，支持重命名、资料管理和返回概览。
主区中央保持聊天与输入；学习动作靠近当前消息或资料选区，不在首页堆满“功能已接入”的卡片。
首次进入显示创建目标、加入资料和继续最近学习；没有真实记录时保持空状态。
右侧辅助工作区采用可拖动分隔条，包含“资料 / 练习 / 笔记”三个视图，按当前操作打开对应内容。
拖动宽度与开合属于布局偏好；关闭面板不删除资料、不结束聊天，也不丢失未提交的作答草稿。
窄窗口将辅助区切换为可返回的单页或抽屉，保留当前标签、阅读位置和焦点；拖动须有键盘等价操作。

“资料”展示解析状态、选中文件和引用定位；点击引用打开原文并高亮对应片段。
“练习”展示题目、作答区、提示层级与提交后的反馈；提交前不把答案放进可见摘要。
“笔记”支持手动编辑和保存选中内容，显示未保存状态、修订和来源；生成建议需用户确认后入库。
聊天中的“解释 / 练习 / 整理”选择只改变工作流意图，不能凭按钮切换宣称后端已拥有相应能力。

## 前端交互与执行能力的边界

当前入口 [main.ts](../src/main.ts) 组装 React 界面，由 Vite 构建；不再按旧 DOM 工作台入口推断实际能力。
[聊天界面](../src/components/application/agent-chat/agent-chat.tsx) 使用 AI SDK `/api/chat`，已有流式呈现和停止入口。
[Vite 适配](../scripts/boardui-chat-api.ts) 只在开发与预览服务中提供服务器路由，模型凭据由服务器环境读取。
静态前端构建和 Tauri 安装包不会因此自动获得常驻模型服务、资料解析器或 Python 运行时。
本机模型配置记录与当前服务器提供方仍需正式打通，不能把保存设置当作连接成功。

前端负责呈现资料、草稿、引用和实际运行状态，提交有稳定身份的命令，并允许取消、重试与恢复。
运行时负责模型调用、资料读取与解析、检索、反馈生成、权限范围、预算和真实执行结果。
存储层负责正文、修订、作答、来源和迁移；解析或模型调用成功但保存失败时，不能显示“已保存”。
题目生成结果先由服务拆成公开题面与私有答案键；作答前只向前端提供题面、允许的提示和输入结构。
运行时按已保存的问题 ID 和版本读取答案键，不信任前端提交的标准答案；完整解析只在提交反馈或主动揭示后返回。
资料解析、索引、检索和引用核对分别报告状态；文件已选中不等于已解析，已解析也不等于索引可查询。
首版可从少量文本 / Markdown 开始，用选定片段建立依据；只有完成解析和页码映射后才开放文本 PDF。
扫描 PDF、OCR、公式识别、联网搜索和大规模知识库各有额外依赖，应独立验收后逐步加入。

## 数据身份、来源与学习证据

学习空间拥有稳定 `learningSpaceId`，保存目标、资料关联和会话关联；联系人独立拥有 `contactId`。
会话沿用稳定 `sessionId` / 当前 thread 映射，运行使用 `runId`，用户命令使用幂等 `requestId`；切换视图、人物或资料标签不新建同一对象。
当前 `nekopapa:chat-threads:v1` 与 `nekopapa.contacts.v1` 分属各自模块，迁移时保留 ID、原始数据和历史关联。
当前共享 ChatHistoryStore 按 ID 合并工作台和联系人历史；选择联系人复用最新相同 contact.id 的 thread.id，进行中的草稿与流式状态仅在当前页面分别保持。
新学习领域通过服务与存储接口拥有状态，不把题目、资料和笔记都塞进聊天组件或配置集合。
桌面持久化以 [会话与文件管理](session-storage.md) 的单写权威方案为目标；未完成前不得承诺跨设备或可靠后台恢复。

资料有 `sourceId` 与不可变的 `sourceRevisionId`，记录内容 hash、原文件来源、解析版本和就绪状态。
引用指向资料修订及具体定位：PDF 页码与片段、Markdown 标题路径与段落、代码提交或文件修订及行范围。
片段 ID、引用 ID 与显示顺序分离；文件更新后旧引用仍能核对旧修订，不能悄悄指向新版同名段落。
无法保留原文时保留来源标识与缺失状态；资料失效或无权限时说明原因，不生成占位引用。
笔记有独立 `noteId`、修订号与来源链；手动改写保留历史，保存冲突提供对比和恢复，不静默覆盖。

题目保存稳定 `questionId`、`questionRevision`、目标版本和生成时的证据快照；换题或修改题目建立新版本。
每次作答保存 `attemptId`、题目及版本、知识点、用户原始答案、时间、提示和答案揭示情况。
重复传输同一提交返回原 attempt，用户主动“再答一遍”才创建新 attempt；评价失败重试只创建新的评价运行，不复制学员作答。
作答接受事务成功后即可显示“已提交”，反馈尚未生成时显示对应状态；不能等模型回复后才临时构造原答案。
反馈记录评价标准及版本、评分方式、证据、模型 / 工具版本和可修订结论；原始作答不可被反馈覆盖。
客观题和可执行任务优先使用明确规则与真实测试；开放题使用可见评价点，并允许用户纠正模型反馈。
模型评价在事务外运行，保存前复核问题、目标与证据版本；期间发生变化时保留原 attempt 并说明需重新评价，不让旧结果覆盖新状态。
返回格式无效、模型无法判定或工具未执行时保存对应失败 / 不确定状态，不补一个看似精确的分数。
掌握情况依据跨次作答、独立完成程度和延迟回忆，显示可追溯证据与“需要再验证”等状态。
不按聊天轮数、阅读时长、模型自评或回答语气生成“掌握 80%”；用户自评独立记录。
复习项关联概念与作答证据，保存到期时间、调度规则版本和人工调整，不修改历史作答来迎合新调度。

## 开发顺序与依赖门槛

按可用闭环推进，不先承诺日历工期；每阶段完成证据通过后再进入下一阶段。
现有 [开发任务清单](iteration-backlog.md) 的编号用于追踪依赖，需在领取时核实现状，不能把计划条目当作已完成。
技术拆分和 `EDU-0–4` 交付门槛见 [源码对照的实施顺序](deeptutor-integration.md#实施顺序与交付门槛)。

### 阶段一：打通可靠的文字学习底座

先完成真实提供方连接、会话持久化、停止 / 重试与稳定运行身份，覆盖 `CHAT-01–03`、`DATA-01–04` 的相关范围。
桌面服务先走 `RT-01 / RT-03` 的进程与协议验证；Coding 执行层专用的 `RT-02` 不作为普通文字学习的强制前置。
既有 `RT-04` 同时含执行引擎验证，若拆出学习底座交付，应更新任务依赖，保留资源打包与安装包运行验收。
浏览器可先验证服务端 API 的纵向流程；桌面发布还须验证安装包资源、凭据读取、服务启动和退出。
验收：真实模型两轮问答可继续，停止保留部分结果；认证失败、离线、重启与保存失败均有可恢复状态。

### 阶段二：第一条资料学习闭环

在阶段一上加入学习空间、选定文本资料、可定位的解释、一道短题、作答反馈、可编辑笔记与手动设日期的复习项。
复用 `CHAT-04` 的上下文与来源边界，优先完成 `PAGE-01–02` 的正文 / 修订和 `FLOW-01` 的受限资料读取。
不必先建通用工作流市场；一次学习操作仍遵循统一 Run、幂等提交、取消和保存契约。
资料量超过明确上下文预算时要求缩小范围；检索尚未实现时不假装已经检索整份教材。
验收：完成下述最小流程，引用逐项可打开，用户答案和笔记重开后保留；无依据时明确回答未找到依据。

### 阶段三：可检索资料、复习与连续课程学习

有足够的真实作答结构后，加入错因整理、概念关联、可调整复习队列和学习空间概览。
资料规模超过选定片段后，先交付 `EDU-2` 的文本 PDF、索引版本、混合检索与来源质量，再扩大课程范围。
用独立资料与问题集验证应该找到的片段、无法回答的问题和引用支持关系，记录实际生效的检索策略，不只验证接口返回成功。
先支持应用内“今日待复习”，后台通知与定时执行另依赖真实宿主调度、时区、休眠与重复触发处理。
进度使用用户确认的目标与已完成任务；掌握状态展示证据数量、时间和提示情况，不输出虚构精确分数。
验收：跨天再次作答形成新 attempt，推迟和跳过可恢复；离线、时区变化及重复打开不重复完成任务。

### 阶段四：项目执行与专业资料扩展

编程执行依赖 `CODE-01–04` 的目录绑定、权限、真实执行与差异验证，沿用自己的工程任务契约。
可靠检索通过后加入多来源证据对照、扫描件与联网资料，分别立项；专题研究先确认提纲、范围与预算，再启动后台主题任务。
复杂学习流程可复用 `FLOW-02–03`，但每步结果、成本、取消和失败重试必须可观察、可追溯。
验收：独立测试项目真实读改验；跨资料引用可定位；模型服务或外部工具失败不伪造完成结果。

## 最小可用版本的逐步验收

1. 新建“线性代数第一章”学习空间，输入一个具体目标，选择已有同伴；取消创建不留下空对象。
2. 加入一份支持的短文本，核对预览与范围；无文本、格式不支持或超预算时保留原文件并给出恢复入口。
3. 围绕选定段落提问，得到带真实出处的解释；点击出处在辅助区定位到同一资料修订。
4. 请求一道短练习，用户先作答，再逐级取提示或揭示答案；草稿在切换辅助标签后仍在。
5. 提交后获得可核对反馈，保存原答案与提示使用情况；重复提交不产生重复 attempt，评价断流后重试不增加一次作答。
6. 用户修正理解，将结论与来源保存为笔记；保存失败时保留草稿，重试不重复创建笔记。
7. 将对应概念加入复习，用户可改时间；此时只承诺应用内复习，不承诺后台通知。
8. 重开应用，通过原空间继续，目标、资料、引用、attempt、笔记和复习关联一致。

以上流程使用独立测试资料与配置；成功、取消、空状态、错误及恢复均需记录证据。
另验收：答案揭示前的接口不含答案键；资料更新后旧引用仍打开原修订；判分期间改题不写入过期评价；删除或失效的资料明确显示缺失。
基础回归执行 `npm run test`、`npm run build` 和 `git diff --check`，补充领域行为与数据契约测试。
真实入口验证鼠标、键盘、面板拖动、窄窗口、引用返回焦点、流式停止和未保存提示。
Rust 或桌面进程改动追加 Cargo 检查、相关测试与桌面构建，并在实际 Tauri 安装包验证重启与服务退出。
浏览器通过不能代替桌面验收；模型 mock 通过不能代替真实提供方、解析器或执行器的集成证据。

参考其知识解析、检索、解题、教学、出题与研究模块的实际调用链，先建设自己的学习产品语义与数据契约。
源码核查固定为 2026-11-06 的 v1.7.2 提交，详细路径与函数证据见 [源码对照](deeptutor-integration.md)；不追随浮动 main 推断能力。

优先借鉴资料指纹、持久问题 ID、答案键由服务读取、幂等作答与评价提交前的版本校验，不照搬其掌握度公式或庞大源码文件。
独立 DeepTutor 服务属于后置可选 adapter；本规划没有安装、运行或接入它，也不要求用户先安装才能使用未来的自研文字学习。
若决定适配，先连接已有服务、验证认证与模块就绪，再处理会话 / turn 映射、序号重放、取消和引用。
其 WebSocket 不能直接替换当前 AI SDK `/api/chat`；知识上传、索引和解题模块各有独立验收。
服务端 turn 内事件序号与 NekoPapa 的 Session 事件序号分别保存，不混用为同一水位；重放已存事件不等于进程死亡后自动继续执行。
由 DeepTutor 执行的会话保持其服务端数据权威，NekoPapa 保存映射和自身笔记 / 作答，禁止双向复制出两份可写历史。
服务离线时仍可阅读已保存的本机笔记与作答，执行入口说明不可用；不自动偷偷切换到另一模型补答。

## 教学依据与尚待验证事项

Karpicke 与 Roediger（2008）的原始研究摘要报告：词汇学习任务中，学会后继续检索能改善延迟回忆；学习者自我预测与实际表现不一致。
因此先作答后反馈、保留延迟练习是合理设计依据；该实验不能直接证明 NekoPapa 对数学推导、编程或专业判断同样有效。
来源：[Science 原始论文 DOI](https://doi.org/10.1126/science.1152408)，[原始摘要记录](https://pubmed.ncbi.nlm.nih.gov/18276894/)。
Cepeda 等（2008）的原始研究摘要报告：事实学习的复习间隔效果与目标保留时间有关，间隔并非越长越好。
因此允许用户设置目标时间并根据后续作答调整复习；不把固定“1、3、7 天”包装为对所有学习都最优。
来源：[Psychological Science 原始论文 DOI](https://doi.org/10.1111/j.1467-9280.2008.02209.x)，[原始摘要记录](https://pubmed.ncbi.nlm.nih.gov/19076480/)。
上述两项于 2026-11-08 经 Europe PMC 的原始研究摘要与 DOI / PubMed 元数据核对；未完成付费全文的方法与效应量复核。
待小范围真实用户验证：提示是否过早泄露答案、反馈是否可理解、复习负担是否合适、引用是否足以支撑解释。
课程资料解析质量、开放题评价可靠性、模型成本和桌面运行时分发均待独立实验，不在本规划中虚构效果与工期。
资料中的文字视为学习内容，不授予工具权限或更改系统指令；读取范围和外部发送由实际执行契约决定。
每阶段交付更新实际能力、测试证据和限制，再将对应入口从“待接入”改为可用。
