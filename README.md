# NekoPapa

带桌面陪伴的个人 Agent 工作台。用一个桌面客户端组织聊天、项目、页面和工作流，让同一个角色既能陪你聊日常，也能协助完成工作。

产品分为两种模式：**普通模式自研聊天陪伴 Agent，并逐步加入工作流；Coding 模式直接集成 Pi Coding Agent，围绕它进行二次开发。**

**当前状态：已实现可运行的桌面导航壳。** 第一轮开发聚焦 Codex 风格的双层侧栏和 Notion 风格的顶部标签栏。侧栏分组、搜索、新建条目、重命名、收藏、标签切换与关闭、侧栏宽度调整及本地布局恢复已经可用；主内容区暂时只有占位视图。

普通聊天、Pi、工作流、Live2D 透明桌面窗口和独立 Agent 工作区仍属于后续开发内容。当前的项目、会话和页面条目用于验证导航；创建 Coding 条目只建立工作台索引，尚未选择真实目录或启动 Pi。连接器、记忆、任务与设置目前提供导航入口。

## 技术栈

沿用原来的 **TypeScript + Tauri** 客户端方案。Tauri 的 Rust 宿主管理桌面窗口和系统能力，Agent 逻辑计划运行于独立的 Node.js 进程。

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 客户端界面 | TypeScript + Vite | 已实现导航壳；聊天、页面编辑和 Live2D 待接入 |
| 桌面宿主 | Tauri 2 / Rust | 已实现原生主窗口；透明窗口、多窗口和 Agent 进程管理待开发 |
| 普通 Agent | TypeScript / Node.js（计划） | 自研陪伴逻辑、记忆、工具和后续工作流 |
| Coding Agent | Pi SDK / Node.js，TypeScript 适配层（计划） | 嵌入 Pi 并维护产品扩展 |

当前界面直接使用 TypeScript、CSS 和系统字体，导航状态与视图、交互分开管理。前端依赖锁定于 `package-lock.json`，Rust 依赖锁定于 `src-tauri/Cargo.lock`。

后续 Node.js Agent 作为随应用分发的独立运行进程，由 Tauri 宿主启动和管理；接入方式参考 [Tauri 官方 Node.js sidecar 文档](https://v2.tauri.app/learn/sidecar-nodejs/)。实际打包方式、依赖兼容性和通信协议在接入 Pi 时验证，目前尚未实现。

## 本地开发

需要 Node.js `^20.19.0 || >=22.12.0`、npm、Rust stable，以及对应平台的 Tauri 系统构建依赖。macOS 需要可用的 Xcode 开发工具。当前前端版本为 TypeScript 7.0.2、Vite 8.3.2，Tauri API、CLI 和 Rust 宿主版本为 2.12.1。

```bash
npm ci
npm run desktop
```

桌面命令会同时启动 Vite 和 Tauri 原生窗口。单独预览前端可运行 `npm run dev`，地址为 `http://127.0.0.1:1420`；它用于界面调试，窗口拖动、原生按钮等桌面行为需要在 Tauri 中检查。

```bash
# TypeScript 检查与前端构建
npm run build

# Rust 宿主检查
cargo check --manifest-path src-tauri/Cargo.toml

# 打包桌面应用
npm run desktop:build
```

macOS 应用输出位于 `src-tauri/target/release/bundle/macos/NekoPapa.app`。开发验证可用 `npm run desktop:build -- --debug`，对应输出位于 `src-tauri/target/debug/bundle/macos/NekoPapa.app`。当前打包目标为 `.app`，发行签名与公证尚未配置。

已在 macOS Apple Silicon 上完成前端构建、Rust 检查、原生应用打包与窗口交互验证；验证环境为 Node.js 25.7.0、Rust 1.96.0。Windows 和 Linux 尚未验证。

### 当前导航操作

- 外侧图标栏提供首页、陪伴、任务、工作流、代码项目、连接器和设置入口。
- 内侧栏可展开空间和项目，通过分组菜单新建条目、重命名，通过条目菜单管理收藏。
- 顶部使用随标题收放的紧凑圆角标签，支持打开、切换、关闭和新建；标签过多时提供列表切换入口，调整窗口宽度后保持当前标签可见。右键可关闭其他标签或右侧标签，同一条目重复打开时复用已有标签。
- 拖动侧栏右边缘调整宽度，双击恢复默认；聚焦边缘后可用左右方向键调整，`Home` 恢复默认。
- 搜索按名称和所属分组匹配工作台内容，可用方向键选择、回车打开。

导航图标采用统一的 20px SVG 绘制网格、圆头线条与一致的留白。侧栏和标题栏共用浅灰背景，选中状态使用轻量底色；顶部取消整格分隔线，内容区保留细小圆角。

桌面端使用独立的猫形对话气泡 Logo，采用深灰与暖白配色。已接入侧栏工作台标题、首页、浏览器图标及原生应用打包；生成源图、提示词和图标导出方式见 [桌面端 Logo](docs/brand/nekopapa-logo.md)。

| macOS 快捷键 | 操作 |
| --- | --- |
| `⌘N` / `⌘T` | 新建普通会话条目 |
| `⌘W` | 关闭当前标签，保留侧栏内容 |
| `⌘⇧T` | 恢复最近关闭的标签 |
| `⌘K` | 搜索工作台 |
| `⌘B` | 展开或收起内侧栏 |
| `⌥←` / `⌥→` | 导航后退或前进 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 切换标签 |

导航条目、分组、收藏、最近访问、打开的标签、侧栏宽度和折叠状态保存在当前客户端的 `localStorage` 中。浏览器预览和原生客户端各自保存布局。后续真实聊天记录、页面正文及凭据会使用对应的存储模块。

## 产品形态

NekoPapa 的长期形态是类似 Notion 的个人工作台：会话、页面、项目与任务都有归属，Agent 可以读取选定资料、执行工作流，并把结果保存为可继续使用的内容。

桌面体验由三个形态组成：

| 形态 | 职责 | 使用方式 |
| --- | --- | --- |
| 主窗口 | 导航、普通聊天、Coding 会话、页面与成果 | Codex 风格侧栏，Notion 风格顶部标签页，主区随当前标签切换内容。 |
| Agent 工作区 | 当前运行、步骤进度、待确认操作、结果和日志 | 独立悬浮在桌面，也可从主窗口打开对应任务详情。 |
| Live2D 陪伴体 | 角色呈现、简短反馈和快捷入口 | 独立无边框透明窗口，直接显示在桌面，可拖动、显示和隐藏。 |

主窗口中角色以头像呈现，完整 Live2D 模型显示在桌面。主窗口最小化或收起后，工作区与陪伴体可以继续显示；关闭整个应用时，由宿主统一处理运行任务和窗口退出。

三个形态读取同一份应用状态。聊天输入、任务确认、取消和角色快捷操作都回到同一条处理路径，避免多个窗口各自维护一套任务或会话。

## 两种 Agent 模式

| 项目 | 普通模式 | Coding 模式 |
| --- | --- | --- |
| 目标 | 日常交流、连续陪伴，逐步处理生活与工作中的小任务 | 围绕选定代码项目进行理解、修改、调试与验证 |
| Agent 实现 | 自研 Companion Agent | 集成 Pi Coding Agent 并二次开发 |
| 主要上下文 | 当前会话、角色设定、相关记忆、用户选定的页面 | 项目目录、项目说明、代码资料与 Pi 会话 |
| 工具范围 | 按迭代增加资料查询、页面操作和业务连接器 | 通过 Pi 适配层接入编程工具与产品扩展 |
| 会话与数据 | NekoPapa 管理普通会话、记忆与工作流记录 | Pi 管理 Coding 会话；NekoPapa 管理项目关联、标签和展示索引 |
| 内容呈现 | 简洁消息气泡，工作流步骤按需展开 | 对话中展示代码、工具进度和文件变更，详细内容在标签页打开 |
| 成果 | 对话、记忆、页面、工作流结果 | 文件改动、变更说明、执行结果和验证记录 |

模式是**会话的属性**。新建会话时选择普通或 Coding，Coding 会话还需要选择项目目录。不同模式可以在顶部标签页同时打开，切换标签不会把另一会话的运行环境覆盖掉。

两种模式共用客户端、角色外观、模型配置入口和任务展示方式，各自拥有上下文与调度逻辑。普通模式的个人记忆默认用于普通会话；向 Coding 会话提供页面或个人资料时，明确选择要引用的内容。

## 界面与视觉

### Codex 侧栏 + Notion 顶部栏

主窗口采用一套统一布局：

- **最左窄图标栏**：全局导航、任务入口和设置。
- **内侧分组栏**：可展开的空间、项目、页面与会话，支持缩进层级、收藏和最近访问。
- **顶部标签栏**：同时打开普通会话、Coding 项目、页面、任务和成果，提供标签切换、关闭及新建入口。
- **主内容区**：显示当前标签对应的聊天、页面、代码变更或运行详情。
- **首页**：简洁欢迎语和输入入口，可以选择模式、当前角色与引用资料。

侧栏解决“内容放在哪里”，顶部标签解决“当前同时打开了什么”。同一对象在侧栏与标签中保持相同标识，切换后恢复其滚动位置、输入草稿和视图状态。

关闭标签只关闭视图；删除内容、取消任务和关闭应用分别提供明确动作。持续运行的任务可以在桌面工作区继续观察。

### 聊天形式与配色

普通聊天借鉴即时通讯的消息结构：角色消息在左侧，用户消息在右侧，配头像、时间分隔、消息气泡和固定输入区。支持流式回复、停止生成、保留失败输入和重试。

**气泡与输入区统一使用黑白灰视觉：白色或浅灰气泡、深灰文字、深色主动作按钮。** 用户与角色通过位置、头像和细微背景差异区分。微信仅作为消息排列与输入方式的参考，配色遵循 Codex / Notion 的中性风格。

Coding 会话沿用相同的外壳，根据内容展开代码块、工具调用与结果。文件变更和长输出可在独立标签页阅读，保留对话区的可读性。

图标、字体、间距、圆角和状态样式在主窗口与悬浮工作区中共用。Live2D 模型保留角色自身颜色，完整模型的呈现由透明桌面窗口承担。

### 桌面陪伴与工作区

陪伴体提供聊天、任务、角色设置等简短入口。点击入口时定位到相应会话、标签或工作区，避免创建重复的运行实例。角色的等待、回复和执行反馈由实际会话与任务事件驱动。

Agent 工作区按需显示：

- 当前任务的模式、所属会话、运行阶段和正在执行的步骤。
- 尚未获得授权的操作、具体输入及确认或跳过入口。
- 实际工具结果、失败原因、取消状态和执行日志。
- 返回主窗口会话或成果页面的入口。

工作区能够独立显示与关闭；关闭其视图不等于取消任务。已经授权的范围在本次运行内复用，需要新决定时再呈现待确认项。

## 普通模式：从陪伴到工作流

### 第一版：自然聊天与连续陪伴

先完成每天能使用的交流流程：

1. 配置模型连接、角色称呼和交流偏好，发送消息并收到真实回复。
2. 保持角色语气与当前对话的一致性，用户想倾诉时回应当下的话，需要建议时再讨论办法。
3. 本地保存会话，重启后可继续；支持新建、重命名、分组和删除会话。
4. 用户主动添加记忆，模型提出的记忆建议经确认后保存；记忆可查看、修改和删除。
5. 桌面 Live2D 与会话共用角色配置，支持移动和隐藏，模型加载失败不阻断聊天。

自研 Agent 负责角色上下文、相关记忆选择、模型调用、消息流、取消与失败恢复。模型接入通过适配层配置，提供方随实际需要选择。

聊天记录与长期记忆分别管理。修改记忆后，新请求使用更新后的值；删除后停止检索该条记忆。删除会话时明确说明关联记忆的处理方式。

### 后续版本：工具与工作流

普通模式逐步增加受控工具，形成“理解需求 → 组织步骤 → 执行 → 汇总 → 保存成果”的流程。

第一个工作流可选用：**从用户选定的本地资料中查找内容，整理摘要，并保存为工作台页面。** 先验证真实输入、真实工具结果与可重新打开的成果，再增加更多场景。

工作流定义记录步骤、输入、输出、依赖和条件；每次运行单独记录当前节点、状态、结果和必要的授权。支持取消、失败反馈和从允许的节点重试。产生外部写入的步骤需要处理重复执行，重启后先核对已执行记录再决定恢复方式。

运行状态统一为：准备中、运行中、待确认、停止中、已完成、失败、已取消。收到请求仅代表开始处理；完成状态依据实际执行结果。

随后再加入可复用模板、条件分支、连接器与定时触发。定时工作流需要用户明确配置；语音和主动问候根据日常使用反馈安排。

## Coding 模式：集成 Pi 并二次开发

这里的 Pi 指 Pi Coding Agent / pi-mono 项目。官方仓库当前为 [earendil-works/pi](https://github.com/earendil-works/pi)，产品入口为 [pi.dev](https://pi.dev/)。

### 接入路线

优先在 Node.js 运行时中直接嵌入 Pi SDK，通过独立的 `pi-adapter` 封装其会话和事件。官方当前 SDK 包为 `@earendil-works/pi-coding-agent`，提供创建会话、发送请求、订阅事件与停止运行的接口。参见 [官方 SDK 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)。

Tauri 的 Rust 宿主负责管理 Node.js Agent 进程，客户端通过宿主与该进程交换请求和事件；Pi SDK 嵌入 Node.js 进程内。通信协议和分发方式在实际接入时验证。需要直接使用 Pi 子进程接口时，可选用官方 [RPC 接口](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)，默认路线仍是 SDK 嵌入。

实际接入时锁定 Pi 版本和依赖，按该版本复核接口。当前仓库尚未安装或集成 Pi，也没有完成运行验证。

### 二次开发范围

NekoPapa 负责产品层的能力：

- 在侧栏选择项目、建立 Coding 会话，并显式绑定工作目录。
- 把 Pi 的消息、工具进度与结果转成主窗口和桌面工作区的展示事件。
- 展示文件变更、命令输出、失败原因和实际验证结果。
- 管理运行取消、会话恢复、项目关联、标签与页面成果。
- 通过 Pi 的扩展、技能和提示模板加入产品工具、上下文与工作流衔接。

可执行扩展使用官方 [Extensions 接口](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)，并按需要使用 [Skills](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md) 和 [Prompt Templates](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/prompt-templates.md)。优先将产品能力维护在适配层和扩展中，必须修改上游核心时再记录补丁与升级影响。

### 集成边界

Pi 会话存储是 Coding 对话的权威来源；应用存储项目、空间、标签与 Pi 会话的关联，避免维护两份独立可写的 Coding 历史。请求接受、流式消息、工具执行与整次运行完成分别处理，界面依据匹配的运行事件更新状态。

项目目录决定上下文和工具基准路径。文件、进程与凭据的访问边界由宿主和产品工具策略实现；Pi 本身使用启动进程的权限，工作目录不等于操作系统沙盒。依据见 [官方权限说明](https://github.com/earendil-works/pi#permissions--containerization)。

普通模式使用自身注册的工具集，Coding 模式通过 Pi 适配层执行。模式切换和窗口切换只改变当前视图，不把普通会话隐式转成具有编程工具权限的会话。

## 工作台内容与长期目标

从会话逐步发展到类似 Notion 的个人工作台：

| 内容 | 用途 | 建设顺序 |
| --- | --- | --- |
| 空间与项目 | 组织普通会话、Coding 目录与相关成果 | 基础版本建立分组和项目关联 |
| 会话 | 保存交流与任务发起过程 | 首先完成普通会话，再接入 Pi 会话 |
| 页面 | 保存笔记、摘要、计划和生成结果 | 先支持简单可编辑文本，再扩展内容类型 |
| 记忆 | 保存确认后的角色偏好与个人事实 | 与聊天记录、页面分别管理 |
| 工作流 | 定义可重复使用的任务步骤 | 先单次运行，再加入模板和触发器 |
| 运行记录 | 保存步骤状态、授权、结果和日志 | 工具接入时同步建设 |
| 连接器 | 访问用户配置的外部应用与资料 | 随真实工作流逐项加入 |

成果有独立标识和来源，可以从会话或运行记录打开，在顶部标签页继续编辑。关闭会话视图不会删除已保存的页面。

更丰富的表格、研究资料、可视化及其他成果类型属于后续扩展。每增加一种类型，都同步考虑保存、重新打开、编辑和导出。

| 应用存储 | 普通会话、空间、页面、记忆、运行记录和 Coding 索引 |
| 模型配置与凭据 | 提供方配置、模型选择和凭据读取，向不同运行时提供明确配置 |

主窗口、工作区和陪伴体订阅带有模式、会话和运行标识的事件。进行中的任务由运行时拥有，窗口重建后从当前状态恢复显示，不依赖某个标签是否仍然打开。

数据优先本地保存，并提供导出与清除入口。在线模型只接收当前请求所需的会话、选定资料与相关记忆。密钥采用宿主适合的凭据存储方式，与聊天内容分开；个人资料和凭据不进入版本库或普通日志。

桌面框架沿用 Tauri，界面和 Agent 适配层使用 TypeScript。Live2D 渲染与分发方案、本地数据库及模型提供方待实际开发选型。先验证透明窗口、Node.js Agent 进程的独立运行、Pi SDK 接入和会话持久化，不以概念图代替运行证据。

## 迭代顺序与完成条件

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1 | 桌面导航壳（已落地） | 两层侧栏、顶部多标签与中性配色一致；分组、搜索、新建、重命名、收藏、标签关闭与恢复、布局保存可用，并通过原生窗口验证。 |
| 2 | 普通陪伴 Agent 与桌面角色 | 真实模型聊天、流式回复、停止与重试可用；会话重启后可继续，记忆可以确认、修改和删除；透明角色窗口可独立显示、隐藏和移动，反馈与会话状态一致。 |
| 3 | Pi Coding 模式 | 绑定测试项目完成真实读取、修改和验证；事件展示、停止、失败反馈与会话恢复正确；普通会话与 Coding 会话相互独立。 |
| 4 | 页面与成果 | 会话或 Coding 结果可保存为页面，在标签中打开、编辑、重新加载和导出；成果与来源保持关联。 |
| 5 | 普通模式工作流 | 一个真实流程完成资料读取、整理与页面保存；工作区显示真实进度，确认、取消、失败重试和重复执行处理均可验证。 |
| 6 | 复用与扩展 | 加入工作流模板、条件分支、连接器和用户配置的触发器；每项扩展都有可观察的结果和恢复方式。 |

每阶段交付可使用的完整流程，再扩展下一项能力。Pi 接入验证使用独立测试项目，桌面窗口、透明渲染和后台运行需要宿主验证；浏览器预览仅作为界面证据。

后续迭代同步更新实际启动命令、锁定依赖、已验证平台与当前限制。
